I now have working existing PowerShell and Python scripts that generate scaled 3D Bismarckturm-inspired models optionally as a birdfeeder or tealight as separate STL files:

- 01_base_and_hopper_birdfeeder_*.stl or 01_base_and_hopper_tealight_*.stl
- 02_hollow_tower_shaft_*.stl
- 03_lift_off_crown_lid_*.stl
- 00_full_bismarckturm_assembly_*.stl

The STL files are intended for 3D printing. I now want to create a separate laser-cutting workflow that uses the same Bismarckturm design as a reference and produces flat, interlocking, flat-pack style model components suitable for cutting from sheet material with a laser cutter.

Please create TWO NEW, equivalent scripts:

1. PowerShell script:
   generate_bismarckturm_laser_parts.ps1

2. Python script:
   generate_bismarckturm_laser_parts.py

These scripts must take one or more existing Bismarckturm STL section files as input and output 2D SVG and/or DXF files containing flat, interlocking model parts. The output must be suitable for import into a CAD package, where I can inspect, adjust, nest, and prepare it for laser cutting.

Do not modify any of the existing Bismarckturm 3D-printing scripts, their STL outputs, or their behaviour.

======================================================================
IMPORTANT DESIGN INTENT
======================================================================

The laser-cut model should be a flat-pack, interlocking sheet-material version of the Bismarckturm, not merely a stack of horizontal cross-sections.

It should preserve the recognisable architectural character of the Bismarckturm model, including:
- the base and hopper section;
- the front portal with columns;
- the door opening;
- the rear and side window openings;
- the hollow tower shaft;
- the lift-off crown lid;
- the overall vertical proportions;
- the “BISMARCK” inscription panel, if practical in the chosen material and scale.

The scripts must support both model variants:
- Birdfeeder
- Tealight

The Birdfeeder and Tealight versions differ only in the base and hopper section:
- Birdfeeder: includes the seed-flow guide and enlarged front seed outlet.
- Tealight: has no seed-flow guide and includes a central tea-light seating area.

The hollow tower shaft and lift-off crown lid are shared between both variants.

-OutputFormat <SVG,DXF>
- Comma-separated output formats.

-OutputDirectory <path>

======================================================================
INTERLOCKING JOINTS
======================================================================

Create a parametric tab-and-slot joint system.

Requirements:

- Tabs must be designed for the selected material thickness.
- Slots must be sized to accept the tabs after kerf compensation.
- The finished joint clearance must equal the user-specified -JointClearance value.
- Use the supplied -Kerf value in the joint calculation.
- Do not assume that a tab and slot drawn at identical nominal dimensions will fit correctly.
- Provide a configurable fit strategy:
  - “slip”: easy assembly, suitable for glued construction;
  - “snug”: close locating fit;
  - “press”: tight interference fit, but warn that laser-cut press fits can be unreliable.
- Default fit strategy: “slip”.

Use a clear and documented kerf/clearance model. For example, for a tab of nominal width W, total kerf K, and desired finished clearance C:
- The finished tab width should be W.
- The finished slot width should be W + C.
- The drawn slot centre-to-centre distance should account for kerf so that the finished slot is W + C.
- Document the exact formula used in the script and User Guide.

Avoid fragile joints:
- Do not create tabs or slots narrower than the material thickness unless the user explicitly permits it.
- Maintain sensible minimum edge distance between slots and part edges.
- Avoid placing slots too close together or too close to corners.
- Add small end reliefs where necessary to prevent stress concentrations and make assembly easier.
- Ensure that tabs do not collide with windows, the door, the seed outlet, the tea-light cavity, or other internal features.

======================================================================
VALIDATION REQUIREMENTS
======================================================================

Separate validation into input-STL validation and generated 2D-output validation.

A. Input STL validation

Before using an input STL, validate that:

- The STL file exists and can be opened.
- The STL contains a valid triangular mesh.
- The mesh can be interpreted as a closed, manifold, watertight solid.
- If the STL is not manifold or watertight, print a clear warning identifying the file and the issue.
- Do not silently continue if the defect is severe enough to prevent reliable cross-section extraction or 2D part derivation.
- Check that the STL has a sensible bounding box and units consistent with the Bismarckturm model.
- Report the STL bounding-box dimensions in millimetres.
- Confirm that the supplied base STL matches the selected -Birdfeeder or -Tealight model type where identifiable from the filename or geometry.
- If the user supplies a full assembly STL, warn that automatic extraction of individual flat panels may be imperfect and recommend using the separate section STLs.

B. Generated 2D geometry validation

For every generated 2D part, validate that:

- Every cut path is a closed polyline or closed polygon.
- Every internal opening is represented as a closed path.
- No cut path is self-intersecting.
- No cut path contains duplicate, zero-length, or degenerate segments.
- No part outline intersects another part outline on the same cutting sheet.
- No internal opening intersects the part outline.
- No tab intersects another tab, a slot, an opening, or the part boundary.
- Every tab has a matching slot on the intended mating part.
- Every slot has a matching tab on the intended mating part.
- Tab and slot geometry is compatible in position, orientation, width, depth, and count.
- The finished tab/slot clearance equals the user-specified -JointClearance value after kerf compensation.
- Tabs and slots are not narrower than the material thickness unless the user explicitly enables an exception.
- Slots maintain a sensible minimum distance from part edges and corners.
- Slots do not fall too close to one another.
- Slots do not intersect the door, windows, seed outlet, tea-light cavity, internal structural features, or other openings.
- Part outlines remain within the configured sheet area after nesting.
- Nested parts maintain a minimum separation from one another and from the sheet edge.
- The minimum separation accounts for kerf: use at least kerf/2 on each adjacent cut path, plus any configured clearance margin.
- No part is placed partly outside the sheet.
- No part overlaps the sheet margin.
- All output geometry uses millimetres.
- All SVG and DXF files are exported at 1:1 scale.
- SVG and DXF outputs contain equivalent geometry and use consistent coordinate systems.
- Cut, engraving, score, construction, and label information are assigned to clearly separated layers, colours, or line types.
- Engraving and score paths do not interfere with cut paths.
- Part labels remain readable and do not overlap cut lines or openings.
- Any generated test coupon contains clearly labelled candidate tab/slot sizes and can be cut from scrap material.

C. Assembly validation

Before final output, perform a logical assembly check:

- Confirm that every required mating edge has a compatible joint.
- Confirm that each tab/slot pair is assigned to the correct mating part.
- Confirm that no two parts claim the same mating edge in a conflicting way.
- Confirm that the assembled parts form a coherent Bismarckturm form.
- Confirm that Birdfeeder and Tealight variants use the appropriate base parts.
- Confirm that the tower shaft and crown lid parts are compatible with both base variants.
- Produce a warning, rather than failing outright, if automatic STL-to-2D derivation creates an ambiguous or potentially imperfect joint.

D. Failure behaviour

If a validation check fails:
- Print a clear, specific error message.
- Identify the affected file, part, layer, joint, or coordinate.
- Explain the likely cause.
- Do not write incomplete, invalid, or misleading SVG/DXF output.
- If a non-critical warning is detected, clearly identify it and allow the user to decide whether to continue only when it does not compromise cut validity or assembly.
